# 07 · 利润池与称桶分配（代理树 + 占成差额制）

> 依据《利润池与称桶分配模式说明文档》（2026-08-15）与
> 《代理称桶制度与上下级分成机制说明文档》（2026-08-17，加入上下级分成）实现。
> 本文是实现口径的最终定义；与需求文档歧义处以本文（已与产品对齐的默认值）为准。

---

## 1. 收入端：游戏抽水（毛利润）

| 场景 | 抽水比例 | 配置项 |
|---|---|---|
| 玩家（闲家）赢 | 盈利 × **3%** | `fees.playerRakeRatio` |
| 庄家赢 | 实收 × **5%** | `fees.bankerRakeRatio` |
| 平局 / 输方 | 不抽 | — |

- 所有抽水实时入账平台科目 `PLATFORM_RAKE`，即当日**毛利润**。
- 历史局兼容：拆分前的旧局快照只有单一 `rakeRatio`，进行中的旧局两侧均按旧值执行。

## 2. 支出端：公司成本

```
公司支出 = 公司总流水 × 支出比例（默认 2.5%，可配置）
```

- 「公司总流水」= 当日全体用户 `TurnoverDaily.selfCents` 合计（**有效下注**口径，与推广返水一致）。
- 账面计提，不产生真实转账，仅用于计算净利润池。

## 3. 净利润池与负结转

```
净利润池 = 当日抽水合计 − 公司支出 + 前日负结转
```

- 净池 **> 0**：按第 4 节分配，未分完的余数归公司留存。
- 净池 **≤ 0**：当日不分配（`NO_DISTRIBUTION`），负额自动结转次日冲抵（`carryOutCents`）。

## 4. 代理树与占成差额制（130 点制）

### 4.1 代理树

- 系统有一个**总后台官方邀请码**（固定 UID `8888888888`，启动时自动建立）。
  邀请关系 / 二维码走**推广返水**；**称桶分成**只在后台单独绑定或加成代理，两套并行、互不影响。
- 后台只建立**第一层代理**（无上级）：从已进场的真实玩家中搜索并加成；加成时会把该玩家已经邀请、尚未归属的直属好友补绑到他名下。
- 加成之后，该代理用自己的 UID / 二维码邀请好友即可自动归属（`AgentPlayer.source = REFERRAL`）；后台也可手动绑定（`MANUAL`）。一个玩家最多归属一个代理。
- 下级代理由上级在玩家端「玩家列表 → 升级代理」发展。玩家升级为代理后原归属记录转换（删除 `AgentPlayer`，其后续流水计入自己名下）。

### 4.2 占成约束

- 上级给下级设占成必须**至少预留 `minReservePoints`（默认 5）点**：下级点数 ≤ 上级点数 − 5。
- 每一级同理向下传导；改点数时同时受「上级 − 预留」上限与「最大直属下级 + 预留」下限约束。

### 4.3 分成公式（差额制）

```
自身利润 = 净池 × (自身流水 ÷ 公司总流水) × (占成点数 ÷ 130)
差额利润 = Σ 净池 × (直属下级团队流水 ÷ 公司总流水) × ((自身占成 − 下级占成) ÷ 130)
代理所得 = 自身利润 + 差额利润
```

- 「自身流水」= 直属玩家流水 + **代理本人流水**；「团队流水」= 自身流水 + 所有下级团队流水。
- 上级不对下级业绩重复领取完整占成，只赚占成差额；整条代理线合计恒 ≤ 顶层代理占成上限，
  同一笔利润不重复分配（守恒，有单测覆盖文档 A65→B55→C45→D40 案例）。
- 金额按分向下取整，残差归公司留存；**停用（DISABLED）代理不领取**（份额归公司），
  其团队流水照常向上聚合、上级照常按差额领取。

```
标准案例（需求文档 4.3）：A65 → B55 → C45 → D40，D 线基础利润 RM10,000：
D = 10,000 × 40/130 = RM3,076.92；C 差额 5 点 = RM384.61；
B 差额 10 点 = RM769.23；A 差额 10 点 = RM769.23；合计 = RM5,000（− 取整残差）
```

## 5. 结算流程（两阶段）与资金流

1. **生成报表**：每日后台任务（可关）在返水结算后自动生成**前一马来日**报表，
   落库 `ProfitPoolDaily(PENDING)` + 全量 `AgentProfitShare` 明细（含 0 金额，供前台回放）；不转账。
2. **确认发放**：管理员核对后在后台点「确认发放」→ 状态 `SETTLED`，
   逐笔 `PLATFORM_PROFIT_POOL → 代理 USER_AVAILABLE`（`refType = profit_share`，
   幂等键 `profit-share:{date}:{agentId}`），代理收到 Bot 推送。
3. **作废重算**：`PENDING` 报表未转账，可作废后调整代理/配置再重新生成；`SETTLED` 不可作废。
4. 只能生成已结束的马来日（当日数据仅作实时预估展示）。

## 6. 数据模型

| 模型 | 说明 |
|---|---|
| `Agent` | 代理/股东：绑定平台用户、占成点数、状态、**上级代理**（`parentAgentId`，树形） |
| `AgentPlayer` | 玩家归属（一对一），`source`：REFERRAL 推荐自动 / MANUAL 后台手动 |
| `ProfitPoolDaily` | 每日池：抽水拆分、流水、支出、结转、净池、分配、留存；状态 PENDING/SETTLED/NO_DISTRIBUTION |
| `AgentProfitShare` | 分配明细：自身/团队流水、占成快照、**自身/差额金额拆分**、下级差额明细 JSON |

## 7. 界面

### 7.1 玩家端（仅代理可见，`/api/agent/*`）

- 「我」页新增**代理专属**区块（非代理不显示入口）：称桶报表 / 分成管理 / 玩家列表 / 推荐二维码。
- **称桶报表**（默认昨日，可翻日）：公司数据（总流水/总支出/利润池）→ 我的称桶利润
  （全部 = 代理差额 + 玩家自身）→ 我的代理表（下级团队流水、我的剩余占成、我的利润）
  → 我的玩家表（流水、按我占成折算利润）→ 状态（待发放/已发放/预估/不分配）。
- **玩家列表**：直属玩家（注册时间、累计流水、归属来源）与下级代理两个视角；
  「升级代理」弹层设置占成（上限 = 我的占成 − 预留，显示当前最高可设置）。
- **分成管理**：调整直属下级占成（同样受预留约束，服务端强校验）。

### 7.2 后台（资金 → 利润池分配，SUPER/FINANCE）

- 指标卡 / 计算过程条（差额制公式）/ 近 14 日趋势 / 代理贡献图。
- **两步结算操作台**：① 生成报表 → 核对 → ② 确认发放（二次确认）；PENDING 可作废重算。
- **代理管理**：树形层级展示（第一层标记、缩进），列含自身/团队流水与自身/差额分成拆分；
  新增仅限第一层；改点数带树内合法区间提示；绑定/解绑玩家（推荐归属带标记）。
- 配置：支出比例、称桶基准、**最低预留点数**、自动生成开关。
- 分配历史：状态含「待确认发放」，明细展示自身 + 差额拆分。

## 8. 配置项（存于 `GameConfig`，scope=PLATFORM，key=profitPool）

| 配置 | 默认值 |
|---|---|
| `expenseRatio` 公司支出比例 | 0.025（2.5%） |
| `bucketBase` 称桶基准 | 130 |
| `minReservePoints` 最低预留点数 | 5 |
| `autoSettle` 每日自动生成报表 | true（发放始终需后台确认） |
| `tierPresets` 占成预设 | 普通50 / 高级60 / 核心65 / 股东70 |

## 9. 与需求文档的差异澄清（已按默认值实现）

| 需求文档表述 | 实现口径 |
|---|---|
| 占成写作「65%」 | 点数制：65 点 ÷ 基准 130，与文档算式 `÷130×65` 一致 |
| 「自身流水 = 直属玩家产生的流水」 | 代理本人下注流水**计入自身流水**（否则该部分利润无人认领） |
| 文档金额四舍五入（如 384.62） | 分为单位**向下取整**（384.61），残差归公司留存 |
| 老玩家归属 | 推荐自动归属仅对**新注册**生效；存量玩家由后台手动绑定 |
| 邀请人不是代理时 | 沿邀请链向上找**最近的启用代理**归属；找不到则不归属 |
| 停用代理 | 不领取（归公司留存），团队流水照常聚合、上级照常拿差额 |
| 与推广返水的关系 | 并行运行：返水走 `PLATFORM_REBATE`，称桶走 `PLATFORM_PROFIT_POOL`，互不影响 |
| 历史已结算数据 | 旧平面制明细全部视为自身利润，展示兼容 |
