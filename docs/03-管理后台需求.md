# 至尊牛牛 — 管理后台需求说明书

> 对应 PRD：`01-产品需求文档-PRD.md` 第 7 章。  
> 使用对象：运营、审核客服、财务、超级管理员。

---

## 1. 概述

管理后台是运营中枢，与玩家端（Bot / Mini App / 群）共用同一业务数据库，独立登录与权限体系。

**后台负责：** 审核、推送、游戏参数、网页游戏房、红包脚本、对局监控、TNG 对账、多 Bot（入口/通知）、财务调账与报表。  
**后台不负责：** 替代局引擎自动结算（可监控与异常干预）；Telegram 群内指令对局（已取消）。

---

## 2. 账号与权限

### 2.1 角色

| 角色 | 权限范围 |
|---|---|
| 超级管理员 | 全部模块 + 账号权限管理 |
| 运营 | 推送、公告、游戏配置、房间、红包脚本（不含大额调账） |
| 审核/客服 | 实名审核、用户查询、设备解绑、备注 |
| 财务 | 流水、对账、抽水/备付报表、调账（可配置需审批） |

### 2.2 安全

- 账号密码登录；建议支持 2FA。  
- 敏感操作写审计日志：操作者、时间、前后值、IP。  
- 银行账号、DuitNow、Bot token 等脱敏展示。

## 3. 模块需求

### 3.1 仪表盘

- 待实名审核数量  
- 今日投注流水 / 抽水合计  
- 进行中的对局数  
- TNG 在途金额 / 对账异常数  
- 推送失败数（近 24h）  

### 3.2 用户中心

| 功能 | 说明 |
|---|---|
| 搜索 | UID、Telegram ID、昵称、DuitNow、银行账号后四位 |
| 详情 | 邀请人/下级、设备、KYC、余额、冻结、最近对局 |
| 操作 | 封禁/解封、备注、协助查看邀请链接 |
| 银行户口 | 查看；客服协助更换（记审计） |

### 3.3 实名审核

| 功能 | 说明 |
|---|---|
| 列表 | 待审 / 已通过 / 已驳回 |
| 字段 | 姓名、DuitNow、银行名、账号、户名、提交时间、TG 信息 |
| 通过 | 更新状态 + 触发 Bot「实名认证已通过」推送 |
| 驳回 | 必填原因 + 触发驳回推送（如启用） |

### 3.4 设备管理

- 查看当前绑定 device_id、绑定时间。  
- **解绑设备**：仅客服/超管；解绑后用户需在新设备重新绑定。  
- 记录操作原因。

### 3.5 推送中心

#### 消息类型

1. 系统/游戏通告（开盘、大庄、充值通道等）  
2. 实名状态（多由事件自动触发，后台可配模板）  
3. 奖励通知（牌型王等，事件触发）  
4. 自定义文案  

#### 能力

| 项 | 说明 |
|---|---|
| 模板 | 标题、正文、变量（玩家名、金额、UID…） |
| 人群 | 全部 / 已实名 / 指定房间 / UID 列表 |
| 发送 | 立即 / 定时 |
| Bot 选择 | 指定 bot_id 或按用户 last_bot_id |
| 日志 | 成功/失败、错误码、可重试 |

### 3.6 游戏运营中心：规则与配置

侧栏不再提供全局「游戏配置 / 每日奖励 / 排行榜」入口。运营先从游戏目录选择 `gameCode`，再在单个游戏详情中使用 **实时运营 / 规则与配置 / 每日奖励 / 排行榜 / 虚拟玩家** 五个页签。所有读写请求必须携带当前 `gameCode`，避免跨游戏误改。

结构化配置支持热更新，保存后只对下一局生效；进行中的局继续使用开局时写入的 `Round.configSnapshot`。提现等钱包配置保留在平台系统范围，不归属任一游戏。

「规则与配置」分为两个区域：

1. 结构化数值配置：牌型、下注、费用、局时长、返水、奖励、排行榜和消息模板。
2. 玩家规则说明：标题、摘要、最多 20 个纯文本章节，可保存为草稿或发布；禁止任意 HTML。玩家端只读取已发布版本。

保存前展示变更摘要，配置与规则修改统一写入审计目标 `game:{gameCode}:config` / `game:{gameCode}:rules`，记录前后值、操作者和游戏代码。

| 配置项 | 示例 |
|---|---|
| 牌型倍数 | 豹子 17、满牛 15… |
| 普通点倍数 | 1–10 点各自倍数 |
| 闲赢抽水 % | 默认 5 |
| 庄赢抽水 % | 默认 5 |
| 竞标倒计时 | 秒 |
| 下注倒计时 | 秒 |
| 抢包超时 | 秒 |
| 下注/梭哈动态范围 | 房间上限=庄钱×比例×人数系数；玩家上限=余额÷本局最高牌型倍数（默认17，完整RM向下取整）；最终取输入/房间/玩家上限最小值并按该倍数预留最大赔付 |
| 自爆阈值 | 默认点数 ≤3 判自爆（双自爆庄赢）；特殊牌型是否豁免（开关） |
| 抽水规则 | 只抽赢方盈利 5%（闲赢抽闲、庄赢抽庄），与庄家费用并存 |
| 红包人均单价 | 红包总额 = 参与人数 × 单价（示例 30 人 → 31.2） |
| 上庄费比例 | 默认庄钱 × 1% |
| 服务费 | 每场固定金额（默认 38） |
| 最低开局人数 | 整数 |
| 续庄 | 每桌仅一次（开关） |
| 比较策略 | 同级比金额；普通是否先比点数 |
| 撤回下注 | 是否允许发 0 撤回 |
| 红包过期时间 | 抢包倒计时（默认 30 秒） |
| 庄家费用 | 上庄费比例、服务费（固定/比例）、代包费比例；与抽水的并存/替代关系 |
| 群播报模板 | 小助手全部消息文案（开骰、等待发包、开始抢包、成绩单、续庄确认等）可编辑 |
| 群置顶小通告 | 多条置顶通告内容管理 |
| 庄家走势长度 | 成绩单展示最近 N 局走势 |

### 3.7 游戏 / 唯一互动群

领域关系为 **一款游戏 = 一个互动群**。互动群不是可自由复制的牌桌；当前游戏目录只有「至尊牛牛」，后台只能显示并运营至尊牛牛互动群。未来新增互动群时，必须先完成新游戏规则引擎接入。

| 字段/操作 | 说明 |
|---|---|
| 游戏名称 | 由游戏目录固定；至尊牛牛不可改名 |
| 游戏代码 | 唯一标识；当前为 `SUPREME_NIUNIU` |
| 最低人数 | 凑齐后可开局 |
| 启停 | 控制该游戏唯一互动群入口；停止后不再自动开局 |
| 新增游戏 | 不是“新建群”；必须先实现独立规则、状态机、结算与配置命名空间 |
| （已弃用）chat_id / bot_id / 邀请链接 | 旧 TG 群绑定字段 |

### 3.7.1 虚拟玩家（互动群假人）

后台可创建虚拟玩家并**指定所属互动群**（一游戏一群），与该群真人共用竞标/下注/结算账本；玩家端不标注「假人」。后续多游戏上线时，按群分别配置假人。

| 能力 | 说明 |
|---|---|
| 所属群 | 创建时必选互动群；可改绑到其他群（原群离群，新群按原在群状态再入群） |
| 身份外观 | 默认从英文名池随机昵称；头像从系统内置头像库随机匹配（同群优先不重复）；支持单个重抽与批量配名配头像 |
| 可入群 / 聊天 / 竞标 / 做庄 / 下注 / 梭哈 / 续庄 / 掷骰 / 群红包 / 自动认尾包 | 按人配置开关 |
| 自动行动 | 小助手开启时，仅在所属群按竞标概率与下注比例自动参与 |
| 资金 | 真实钱包；可设目标余额自动补款；支持后台补款 |
| 代操作 | 后台可对所属群当前局手动代竞标/下注/掷骰/发言 |
| 限制 | 无 Telegram，不可 Mini App 登录；不计入排行榜与返水流水；单房最多 20 人 |

### 3.8 对局监控

- 列表：游戏、局号、阶段、庄家、庄池、下注人数、认额进度。  
- 详情：出价记录、注单、claims、结算单。  
- **强制取消本局**：冻结原路退回；若已拨红包则进入红包异常处理。  
- **认额录入/补录**：对照发包账号领取明细录入金额，姓名自动预匹配、人工确认（强审计）。  
- **重跑结算**：仅允许在未入账或失败状态，且幂等保护。

### 3.9 红包脚本（核心）

后台控制，不在群内由玩家创建。

| 功能 | 说明 |
|---|---|
| 脚本开关 | 自动 / 半自动 / 暂停 |
| 金额策略 | 总金额、个数、区间、按参与人数生成等 |
| 待确认队列 | 半自动模式下运营点「发送」 |
| 重发 | 创建失败时按规则重试 |
| 取消发包 | 与取消本局联动 |
| 配置快照 | 每局记录当时脚本参数 |

### 3.10 TNG 红包 / 认额 / 对账

> TNG Money Packet 无官方创建 API 与领取回调；红包由发包 TNG 账号在 App 内创建，链接由后台登记后发群；认额靠发包账号内领取明细人工录入。

| 页面 | 内容 |
|---|---|
| 红包登记 | 局号、发包账号、红包链接、总额、个数、发送状态 |
| 认额录入 | 对照发包账号「Money Packet History」逐笔录入：领取人 TNG 姓名 + 金额；系统按实名姓名自动预匹配 user_id，人工确认生效 |
| 匹配异常 | 同名/匹配失败工单：人工指定归属（强审计） |
| 超时处置 | 抢包超时后可选：取消本局（退款）/ 判未抢者弃权 / 补录后继续结算 |
| 对账 | 创建合计 vs 已认额合计；差异列表 |
| 在途 | TNG 在途科目余额与明细 |
| 发包账号管理 | 多个发包 TNG 账号登记与轮换（单账号同时最多 10 个进行中红包、受月度限额约束） |

### 3.11 钱包财务

- 玩家流水查询  
- **充值工单（人工确认）**：玩家提交金额+凭证 → 财务核实实际到账 → 确认入账/驳回；确认前不加余额  
- **提现工单（人工确认）**：玩家发起（DuitNow/银行户口）→ 金额冻结 → 财务审核并线下转账 → 确认完成/驳回解冻  
- 工单状态变更自动触发 Bot 推送  
- 调账（加款/扣款）：原因必填、权限控制  
- 抽水日报/局报  
- 红包备付金耗用报表  
- 奖励发放记录  

### 3.12 每日奖励与排行榜

本节功能均嵌入当前游戏的运营中心，数据以 `gameCode` 隔离。切换游戏后必须重新读取该游戏的数据，不能沿用上一个游戏的表单状态。

**每日奖励（三 Tab 全后台配置）：**

- 棋牌奖励：牌型组合条件、参与门槛（默认下注≥5/梭哈≥50）、金额、每日份数  
- 庄家奖励：做庄次数阶梯（18/28/58/88/108 次及金额）、秒杀奖励（判定金额 0.01、次数 3、奖金 588、份数）  
- 特别奖励：运营自建活动奖励并推送展示  
- 查看用户当日进度、得奖名单、手动补发（审计）  
- 任务 code 仅需在同一游戏内唯一；奖励配置、每日进度、配额和名单不得跨游戏合并

**排行榜：**

- 按游戏启用榜型：积分榜（目标游戏已结算有效下注流水）、棋牌榜（目标游戏牌型统计）、打桩榜（目标游戏做庄次数）  
- 周期（日/周/月）、Top N、昵称脱敏  
- 榜单奖励配置与一键发放 + 群/私聊播报  
- 不适用的榜型可对该游戏关闭；虚拟玩家不参与榜单；发奖幂等键包含 `gameCode`

### 3.12a 推广返水

| 功能 | 说明 |
|---|---|
| 比例配置 | 自身游戏奖励（默认 0.7%）、直属下线（默认 0.5%）、二级下线（默认 0.3%）；改后按生效日期应用，调整需配合公告推送 |
| 有效下注口径 | 固定规则：仅计参与结算的下注；庄家按本局对赌结算总额计（不按庄钱、输赢均返）；撤回/取消局/弃权不计；平局是否计入为开关（默认不计） |
| 层级限制 | 固定最多向上两级（A→B→C→D 时 A 拿不到 D 的返水） |
| 日结任务 | 每日自动汇总三级有效下注 → 按比例快照计算佣金 → 实时发放入玩家可用余额（写流水） |
| 佣金报表 | 按日/按用户：三类流水、比例快照、佣金金额、入账状态 |
| 推广关系 | 查询任意用户的上级（一级/二级）与下线列表、绑定时间、贡献流水 |
| 手动重跑 | 某日结算异常可重跑（幂等，不重复入账） |
| 异常 | 自邀/环状关系检测告警（绑定时已拦截，此处兜底审计） |

## 4. 关键页面流程

### 4.1 实名通过

```
打开待审详情 → 核对姓名/DuitNow/银行
 → 通过
 → 写 kyc=approved
 → 入队推送模板「实名已通过」
 → 用户重载 Mini App 解锁钱包/游戏
```

### 4.2 半自动发包与认额

```
局进入 SENDING_PACKET
 → 后台「待发包」列表出现该局
 → 运营在发包 TNG 账号 App 内创建 Money Packet
 → 后台登记链接 → 点发送 → 网页房推送领取入口
 → 玩家在游戏房点击领取 → 跳转 TNG
 → 运营对照发包账号领取明细 → 认额录入（姓名自动预匹配 + 人工确认）
 → 认额齐全 → 触发结算；超时则选择取消/判弃权/补录
```

### 4.3 更换默认 Bot

```
添加并启用新 Bot → 设置 Menu Button（进入游戏厅）
 → 切换 is_default
 → 新邀请深链改用新 username
 → 旧 Bot 可保留过渡；仅影响入口与私聊推送路由
```

## 5. 验收要点

1. 无超管权限不能改抽水/调账。  
2. 审核通过必能收到 Bot 推送（用户未屏蔽前提下）。  
3. 红包脚本暂停时，群内不会自动出现新链接。  
4. 强制取消后玩家冻结余额全部退回。  
5. 多 Bot 下推送打到正确机器人私聊；对局操作仅在网页房生效。  
6. 所有调账、解绑、补认额可在审计日志查到。
