## 0. 30 秒地图

这是一个 **pnpm monorepo**：Telegram Bot 只做入口和私聊推送；真正对局发生在 Mini App 网页房（WebSocket）；运营在独立 Admin。

| 应用 | 路径 | 端口 | 技术 |
|------|------|------|------|
| 后端 API + Bot + 引擎 | `apps/backend` | `:8080` | Fastify 5 + Prisma 6 + grammY + Redis + Vitest |
| 玩家 Mini App | `apps/miniapp` | `:5173` | React 18 + Vite 8 + HashRouter |
| 运营后台 | `apps/admin` | `:5174` | React 18 + Vite 8，**无路由库**，`useState` 切页 |
| 基础设施 | `docker-compose.yml` | PG `:5432` / Redis `:6380` | Postgres 16 + Redis 7 |

**当前已接入游戏只有一款：`SUPREME_NIUNIU`（至尊牛牛）。**  
领域约束：**一款游戏 = 一个互动群**，不能复制第二张同游戏牌桌。新游戏必须先写规则引擎，再进 `gameCatalog.ts`。

**README 已过时**：里面写的 M3–M6（网页房、TNG、运营、多 Bot）大多已经落地。以本手册和 `docs/00-文档目录.md` 为准。

## 1. 本地启动

```bash
pnpm install
docker compose up -d
cd apps/backend
cp .env.example .env          # 至少填 SEED_ADMIN_PASSWORD
pnpm prisma:push && pnpm prisma:generate

# 三个终端
pnpm --filter backend dev     # :8080
pnpm --filter miniapp dev     # :5173  /api → 8080（含 WS）
pnpm --filter admin dev       # :5174  /api → 8080（含 WS）

pnpm test                     # 只跑 backend Vitest
```

- Mini App 本地可直接开 `http://localhost:5173`（`telegram.ts` 在 DEV/localhost 放行 Telegram 检测）。
- 完整 Bot 能力需要 `DEFAULT_BOT_TOKEN` + `MINIAPP_URL`。
- Redis 挂了后端仍能起，但调度锁会退化为数据库；生产必须 Redis。

## 2. 总架构

```
Telegram App
  ├─ Bot 私聊：/start、菜单「进入游戏厅」、实名/奖励/充提推送
  └─ Mini App
       ├─ 准入：邀请人 → 设备 →（点钱包才 KYC）→ 支付密码
       ├─ 四 Tab：大厅 / 钱包 / 消息 / 我的
       └─ 网页互动群：竞庄 / 下注 / 聊天 / 抢包 / 成绩单

Nginx（生产）
  ├─ Mini App 静态
  ├─ Admin 静态
  └─ /api + /api/game/rooms/:id/ws

apps/backend
  ├─ Fastify HTTP
  ├─ roomHub WebSocket
  ├─ engine/（纯函数，无 IO）
  ├─ services/game.ts（对局编排）
  ├─ roundScheduler 1s tick
  ├─ backgroundJobs 60s tick
  └─ virtualPlayerWorker（假人）

PostgreSQL = 真相源
Redis = 调度锁 / Bot 租约 / 多实例 pubsub
外部：Telegram Bot API、TNG Money Packet（无官方回调）、可选 VPay
```

职责边界：

- Bot **不再**解析群指令、不群禁言、不播成绩单。
- 配置主键是 **`gameCode`**（如 `SUPREME_NIUNIU`）；房间 URL 用 **`roomId`（cuid）**。
- 开局会把配置冻进 `Round.configSnapshot`，后台热更新不影响进行中局。

## 3. 后端分层

```
apps/backend/src/
  index.ts          进程入口：种子数据 → listen → Bot → scheduler → jobs → 假人
  server.ts         Fastify 装配、鉴权装饰器、注册全部路由
  config.ts         环境变量
  bot/              grammY 长轮询；Redis 租约防多实例抢同一个 Bot
  engine/           纯函数：牌型 / 下注 / 结算 / 费用 / 返水 / 续庄判定
  routes/           薄 HTTP/WS 层，只校验 + 调 services
  services/         业务核心（对局、钱包、房间、利润池、推送）
  lib/              prisma / redis / serializable 事务 / crypto / telegram
  data/             预设头像、假人昵称、马来西亚支付机构
prisma/schema.prisma
```

启动顺序（`src/index.ts`）：

1. `buildServer()`
2. `ensureSeedAdmin` / `ensurePlatformAccounts` / 密钥迁移
3. `ensureGameConfigDefaults` / 奖励 / 规则 / **目录互动群** / 官方邀请号
4. Redis → `listen(:PORT)`
5. `startBots` → `roundScheduler.start`（1s）→ `backgroundJobs.start`（60s）→ `initVirtualPlayerWorker`

### 3.1 鉴权装饰器（`server.ts`）

| 装饰器 | 用途 |
|--------|------|
| `authUser` | 玩家 JWT `kind=user` + 设备 `authVersion`；VIRTUAL 用户禁止登录 |
| `authAdmin` | 后台 JWT `kind=admin` + `tokenVersion` |
| `requireAdminRoles(...)` | SUPER / OPERATOR / REVIEWER / FINANCE |
| `requireKyc` | KYC 必须 `APPROVED` |

未绑设备只能打 `/api/me` 和 `/api/onboarding/*`。  
WebSocket **不用** 12h 登录 JWT，要先换 60s 短票：`POST /api/game/rooms/:id/ws-ticket`。

### 3.2 路由注册顺序

`auth → onboarding → settings → gameAdmin → wallet → payments → promotion → admin → game → gameRoom → adminGame → virtualPlayers → operations → internalTng → profitPool → agent → notices → uploads`

## 4. 一局状态机

```
WAITING
  → startRound        BANKER_BID      冻庄钱
  → closeBidding      BETTING         冻 bet + reservedCents
  → closeBetting      SENDING_PACKET  庄家掷骰 / 发包
  → publishPacket     CLAIMING        TNG 或 INTERNAL 抢包
  → expirePacket      CLAIM_EXPIRED   可选 AUTO_TAIL 认尾
  → settleGameRound   SETTLING → FINISHED

任意阶段 → CANCELLED
FINISHED 后 WAITING 可 continueBanker → 新局 isContinued=true
```

推进来源：

- 玩家动作：`routes/gameRoom.ts` → `services/game.ts`
- 倒计时 / 自动开局：`roundScheduler` 每秒 tick（Redis 锁 `niuniu:scheduler:tick`）
- 运营强制：`POST /api/admin/rounds/:id/action`
- INTERNAL 抢完：`finalizeInternalRound` 可立刻结算
- TNG：必须认额（人工或 ingest）后才结算

聊天指令（数字下注、`sh`、掷骰）走 `services/chatCommands.ts`，再回写 `roomHub`。

## 5. 账本（改钱必读）

金额全程 **`BigInt` 分**。禁止直接 `prisma.wallet.update`。

用户 4 科目 + 平台科目：

```
USER_AVAILABLE / USER_FREEZE_BANKER / USER_FREEZE_BET / USER_FREEZE_WITHDRAW
PLATFORM_RAKE / PLATFORM_FEES / PLATFORM_RESERVE / TNG_TRANSIT
PLATFORM_REWARD / PLATFORM_REBATE / PLATFORM_PROFIT_POOL / ADJUST_CLEARING
```

- `wallet.post`：单边入账，`idempotencyKey` **全局唯一**；同 key 必须同 refType/金额，否则抛错。
- `wallet.transfer`：自动写 `:out` / `:in` 双分录。
- 资金路径用 `lib/transaction.ts` 的 `serializable()`，冲突（P2034）会重试。
- 充提幂等键是 `(userId, requestId)`，Mini App 的 `requestId` 按 UID 持久化，WebView 重开会复用。

两本账不要混：

1. **赌资账**：可用 ↔ 冻结 ↔ 结算 ↔ 抽水 ↔ 奖励
2. **红包账**：备付金 ↔ TNG 在途 ↔ 核销/损失  
   `claim.amount` 只用来算牌，再触发赌资结算。

## 6. 利润池 / 代理（现行口径）

旧 `ProfitPoolDaily` **已停止自动生成**，只留历史查询。现行是 `ProfitPoolBatch`：

```
选房间 + 开始局号 + 结束局号
  → range/check → preview → generate（Serializable + 永久锁局）
  → 人工 distribute
```

- 公司总流水 = 区间真人闲家有效流水 + 真人庄家有效流水
- 最终利润池 = 总抽水 − 公司支出（支出比例每批必填）
- 代理分成：130 点差额制（自身利润 + 下级点差）
- `ProfitPoolRoundLock` + gist 排除约束防重入
- `ProfitPoolCutover.maxSeqNo` 以下的旧局 **永远不能** 进新池
- 实现：`services/profitPoolBatches.ts` + `profitPoolRange.ts` + `routes/profitPool.ts`
- 产品说明：`docs/07-利润池与称桶分配.md`

玩家侧代理前台：`/api/agent/*` ↔ Mini App `/agent/*`。

## 11. 二次开发铁律（最容易踩的坑）

1. **`gameCode` ≠ `roomId`**  
   配置、奖励、榜、游戏管理员、预算走 `gameCode`。玩家 URL 和 WS 走 `roomId`。大厅旧深链 `/rewards` 只负责重定向到默认牛牛。

2. **配置冻结**  
   进行中局读 `Round.configSnapshot`。改后台配置只影响下一局。

3. **幂等**  
   Ledger `idempotencyKey`、充提 `requestId`、群红包/打赏/管理员发包都要客户端带稳定 UUID。不要「再调一次当重试」却换 key。

4. **不要直接改 Wallet 字段**  
   绕过 `wallet.ts` 会对不上平台科目，财务对账必炸。

5. **虚拟玩家**  
   `User.kind=VIRTUAL` 不能 JWT 登录，只能 worker 调度。每房有 cap（代码里 `VIRTUAL_ROOM_CAP=20`）。假人流水一般不进利润池闲家侧。

6. **利润池双轨**  
   不要复活 `ProfitPoolDaily` 自动任务。新逻辑只认 Batch + RoundLock。Cutover 之前的局锁死。

7. **TNG vs INTERNAL**  
   INTERNAL 可自动结算；TNG 认额是运营/采集责任。同名歧义进 `TngClaimInbox`，不要强行自动入账。

8. **阶段变更要通知 scheduler / bus**  
   只改 `Round.phase` 不够。`roundScheduler` 和 `gameBus` 驱动假人、仪式、超时。

9. **PostgreSQL `NULL` 过滤**  
   `NOT { adminNote: 'X' }` 会丢掉 `adminNote IS NULL` 的行。必须 `OR: [{ adminNote: null }, { adminNote: { not: 'X' } }]`。利润池用户选择器刚修过这个坑。

10. **Serializable 冲突**  
    资金和对局高并发会 P2034，已有重试；新资金路径请复用 `serializable()`，不要自己开默认隔离级别。

11. **Admin 是巨石文件**  
    新运营能力尽量拆到独立组件（参考 `profit-pool/`），不要继续往 `App.tsx` 塞两千行。

12. **Hash 路由**  
    Mini App 链接必须是 `/#/game/...`。普通 `/game/...` 在 Telegram 里会 404。
