# 游戏管理员与互动群管理

## 1. 定位与权限边界

游戏管理员仍是 `User`（Telegram Mini App 用户），不是平台 `Admin`。平台 SUPER 在「游戏运行中心 → 群管理员」按 `gameCode` 授权；授权不会让用户登录 Web 管理后台。

一个游戏可配置多名管理员，一个用户也可管理多个游戏。权限实时从数据库读取，停用授权后下一次管理请求立即失效，不依赖重新签发 JWT。

当前权限：

- `SEND_BUDGET_PACKET`：从该游戏共享运营预算发送管理员红包。
- `MUTE_MEMBERS`：禁言或解除该游戏互动群内的普通成员。

授权候选人必须是启用中的真人 Telegram 用户。授予预算红包权限前，用户必须完成 KYC 并设置支付密码。

## 2. 数据模型

- `Room.supportHostUserId`：每个互动群一个「客服小妹」席位，绑定一名真人 Telegram 用户。
- `GameAdminAssignment`：`gameCode + userId` 唯一，记录权限、`ACTIVE/DISABLED` 状态和平台创建/更新人。
- `GameBudgetAccount`：每个 `gameCode` 唯一，使用 BigInt 分保存物化余额，数据库约束余额不得为负。
- `GameBudgetLedgerEntry`：不可变预算流水；金额必须为正、余额不得为负，`idempotencyKey` 全局唯一。
- `GameAdminActionLog`：记录管理员红包、禁言、解禁的操作者、目标、IP 和动作快照。
- `RoomMember`：保存当前禁言开始时间、到期时间、原因和操作者授权。
- `GroupPacket`：通过 `fundingSource` 区分 `USER_WALLET` 与 `GAME_BUDGET`；预算红包必须同时关联预算账户和管理员授权。

数据库迁移：`20260819170000_game_admin_management`、`20260821174000_room_support_host`。

## 3. 共享预算资金流

### 3.1 平台拨款

1. SUPER/FINANCE 输入金额与原因并二次确认。
2. `PLATFORM_RESERVE` 借记。
3. 游戏预算账户贷记。
4. 两边流水与平台审计日志在同一个 Serializable 事务内写入。

平台备付金或游戏预算余额不足时，条件更新原子失败，不能出现负余额或并发超扣。每个请求使用 UUID，重复相同请求只回放原结果；同一请求号改变参数会返回 `IDEMPOTENCY_CONFLICT`。

平台可拨余额会先扣除所有活跃群红包未领金额和进行中内部游戏红包义务，避免把玩家红包托管资金重复拨入游戏预算。`PLATFORM_RESERVE` 借记同时使用非负条件更新与数据库 CHECK 约束。

### 3.2 管理员红包

1. Mini App 实时校验 `gameCode + userId + SEND_BUDGET_PACKET`。
2. 验证管理员本人支付密码。
3. Serializable 事务内再次校验授权和支付密码版本。
4. 游戏预算借记，`PLATFORM_RESERVE` 贷记进入红包托管。
5. 玩家领取时从平台托管进入玩家可用余额。
6. 24 小时未领取部分从平台托管借记并贷记回原游戏预算。

预算红包最多 50 份，每份至少 RM0.01；不使用个人钱包的 RM10,000 上限，只受 BigInt 合法范围和游戏预算余额限制。红包卡片显示「管理员福利红包」。

## 4. 禁言语义

### 4.1 成员禁言（游戏管理员）

成员禁言只限制目标成员的社交发布能力：

- 普通文字、表情、贴纸；
- 个人钱包红包；
- 打赏客服。

禁言不限制游戏参与：

- 竞庄金额；
- 普通下注与 `sh金额` 梭哈；
- `0` 撤回下注；
- `/重推` 或发送「重推」；
- 投骰、领取系统红包和领取群红包。

管理员不能禁言自己，也不能禁言同游戏的另一名有效管理员。禁言到期按当前时间自动失效，不依赖后台定时任务。

操作完成后，服务端通过 Redis 控制事件向所有后端实例同步，并只向目标用户的 WebSocket 发送 `moderation` 事件；15 秒会话复验作为事件丢失兜底。互动群只显示匿名化系统提示，完整操作者资料只进入 `GameAdminActionLog`。

### 4.2 全群禁言（平台运营中心）

全群禁言是独立的房间级绝对禁言，只允许平台 `SUPER` / `OPERATOR` 在游戏运营中心操作，不复用成员管理员权限。开启后：

- 玩家端不渲染输入框、工具栏、加号、竞标/下注输入和投骰/续庄控件，只显示「互动群已禁言」；
- WebSocket 拒绝文字、表情、贴纸、竞标、下注、撤回、重推和投骰；
- HTTP 旁路拒绝竞标、下注、撤回、续庄、个人红包、内部/TNG 抢包和打赏；
- 虚拟玩家同样不得发言、竞标、下注、续庄或投骰；
- 当前局计时、超时处理和结算照常完成，但禁言期间调度器、续庄与人工接口均不得开启下一局；
- 历史消息与系统播报仍可查看，运营解除后按当前牌局阶段恢复输入。

状态保存于 `Room.chatMutedAt/chatMuteReason/chatMutedByAdminId`。变更通过 Redis 向所有实例广播 `room_moderation`，玩家重连与 15 秒会话复验均从数据库恢复权威状态。全群禁言不等于结束游戏，也不改变互动群入口。

## 5. API

### 5.1 平台端

- `GET /api/admin/games/:gameCode/game-admins/overview`：管理员、预算、流水和操作记录（后台角色只读可见）。
- `GET /api/admin/games/:gameCode/game-admin-candidates`：搜索候选 Telegram 用户（SUPER）。
- `POST /api/admin/games/:gameCode/game-admins`：创建或恢复授权（SUPER）。
- `PATCH /api/admin/games/:gameCode/game-admins/:assignmentId`：权限变更、停用或恢复（SUPER）。
- `POST /api/admin/games/:gameCode/game-budget/fund`：从平台备付金拨入（SUPER/FINANCE）。
- `POST /api/admin/games/:gameCode/game-budget/reclaim`：回收至平台备付金（SUPER/FINANCE）。

### 5.2 Mini App

- `GET /api/game-admin/me`：本人全部有效游戏授权。
- `GET /api/game-admin/games/:gameCode`：游戏、权限、预算和最近动作。
- `GET /api/game-admin/games/:gameCode/members`：分页搜索成员及在线/禁言状态。
- `GET /api/game-admin/games/:gameCode/actions`：本人管理动作记录。
- `POST /api/game-admin/games/:gameCode/packets`：发送预算红包。
- `POST /api/game-admin/games/:gameCode/members/:userId/mute`：禁言。
- `POST /api/game-admin/games/:gameCode/members/:userId/unmute`：解除禁言。
- `POST /api/admin/rooms/:id/chat-mute`：平台运营设置或解除全群禁言（`{ muted, reason? }`）。

所有 Mini App 管理接口先验证现有 TG 用户会话，再实时验证同一游戏的有效授权和单项权限。

## 6. 运营操作

1. SUPER 打开游戏运行中心，选择游戏并进入「群管理员」。
2. 通过 UID、昵称或 Telegram 用户名搜索候选人。
3. 勾选预算红包、成员禁言权限并授权。需要改群内显示名或头像时，点「改名字/头像」，填写自定义名称并上传图片后保存；互动群会同步，不使用系统头像库。
4. 在「客服小妹」席位搜索并绑定真人账号。绑定后该账号展示为客服小妹专属头像与名称；玩家打赏时，该账号会在互动群里自动发一句感谢语，不出现在打赏弹窗。
5. SUPER/FINANCE 在共享预算卡片拨入资金，填写可追溯原因。
6. 管理员从个人中心进入「游戏管理员中心」，选择游戏。
7. 管理员可搜索成员、设置 10 分钟/1 小时/24 小时/永久禁言，或发预算红包。
8. 平台端可查看预算流水和管理员操作记录；需要立即收权时将授权设为 `DISABLED`。

## 7. 核心错误码

- `GAME_ADMIN_ACCESS_DENIED`：没有有效授权或授权已停用。
- `GAME_ADMIN_PERMISSION_DENIED`：缺少当前操作所需的单项权限。
- `GAME_ADMIN_PACKET_SECURITY_REQUIRED`：预算红包权限候选人未完成 KYC 或未设置支付密码。
- `INSUFFICIENT_GAME_BUDGET`：游戏预算余额不足。
- `INSUFFICIENT_PLATFORM_RESERVE`：平台备付金余额不足。
- `ROOM_CHAT_MUTED`：被禁言用户尝试发布受限内容。
- `ROOM_GLOBAL_MUTED`：互动群处于平台全群禁言，所有玩家输入均被拒绝。
- `CANNOT_MUTE_SELF` / `CANNOT_MUTE_GAME_ADMIN`：目标不可管理。
- `SUPPORT_HOST_USER_NOT_FOUND`：要绑定的客服小妹账号不存在。
- `SUPPORT_HOST_USER_INVALID`：客服小妹只能绑定启用中的真人 Telegram 用户。
- `IDEMPOTENCY_CONFLICT`：请求号已用于不同参数。

## 8. 验收重点

- 跨游戏授权不能访问或操作另一游戏。
- 停用授权后下一请求立即失败。
- 并发预算扣款不得超扣，所有资金变化有双边流水。
- 请求重放不重复扣款，参数冲突明确失败。
- 预算红包领取与过期退款前后账务守恒。
- 禁言目标立即收到实时状态；普通消息被拦，合法游戏指令仍可执行。
- 全群禁言后所有在线玩家立即隐藏完整输入区，游戏指令与 HTTP 旁路同样失败；解除后无需重进房间即可恢复。
- 另一名有效游戏管理员始终不能成为禁言目标。
